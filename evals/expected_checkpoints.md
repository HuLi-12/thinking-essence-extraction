# Expected Checkpoints for Test Prompts

本文件定义每个测试用例的预期合格行为检查点。
在执行 `test_prompts.md` 中的测试时，用检查点判定 PASS/FAIL。

---

## Test 1：1×1 卷积的本质

### 必须包含的检查点

- [ ] R1: 明确指出 1×1 conv 在**每个空间位置**做的是从 C_in 到 C_out 的**线性投影（无空间交互）**
- [ ] R2: 给出参数量公式 `Params = C_in × C_out + bias`，且与 H/W 无关
- [ ] R3: 说明空间分辨率不变（H/W 不受影响）
- [ ] R4: 说明代价——无法建模空间局部关系（与 3×3 对比）
- [ ] R5: 给出可验证实验——如用 1×1 替换 3×3 观察参数量变化和感受野变化

### 禁止出现的错误

- [ ] 只说"调整通道数"而不说"怎么调整"
- [ ] 说"增强特征表达"而不还原为具体变量

---

## Test 2：下采样后增加通道

### 必须包含的检查点

- [ ] R1: 区分 H/W 下降带来的多重影响（FLOPs、activation memory 均下降）
- [ ] R2: 明确指出参数量与下采样无直接关系（参数量由 C 和 K 决定）
- [ ] R3: 提到"用空间预算换通道容量"或等价表述
- [ ] R4: 提到 decoder 需要补偿空间损失
- [ ] R5: 给出可验证实验（如对比 FLOPs 变化、对比不同 C 选择对分割边界的影响）

### 禁止出现的错误

- [ ] 说"语义增强所以增加通道"
- [ ] 说"下采样减少了参数量"

---

## Test 3：ASPP dilation 改小

### 必须包含的检查点

- [ ] R1: 给出 ERF 变化与目标尺度的对齐关系
- [ ] R2: 给出 sampling density（采样密度）的变化
- [ ] R3: 区分大目标（road/building/water）和小目标（barren/agriculture）受不同影响
- [ ] R4: 给出类别级验证（class-wise IoU / scale bucket）
- [ ] R5: Evidence Level 清晰区分：结构事实 vs 机制推断 vs 待验证假设

### 禁止出现的错误

- [ ] 只说"上下文捕获不足"和"更友好"而不给出具体变量
- [ ] 混淆前后类别趋势（road/building 应下降，barren/agriculture 应上升）

---

## Test 4：Decoder 设计审查

### 必须包含的检查点

- [ ] R1: 分析梯度路径长度
- [ ] R2: 分析上采样倍数的分配（4× → 2×+2× 的梯度差异）
- [ ] R3: 指出 1×1 reduce 的信息瓶颈风险
- [ ] R4: 分析 low-level feature（res2）与 high-level feature 的对齐问题
- [ ] R5: 给出代价交换
- [ ] R6: 给出可验证假设

### 禁止出现的错误

- [ ] 只说"设计合理，恢复空间细节"
- [ ] 没有具体瓶颈判断

---

## Test 5：ResNet-50 vs ResNet-101

### 必须包含的检查点

- [ ] R1: 分析 ERF 与 LoveDA 目标尺度的匹配关系
- [ ] R2: 提到 BN 稳定性对少样本类别的影响
- [ ] R3: 区分参数量、FLOPs、有效容量的差异
- [ ] R4: Evidence Level 区分清晰
- [ ] R5: 给出可验证实验

### 禁止出现的错误

- [ ] 说"场景简单"
- [ ] 说"收益递减"而不解释递减的机制

---

## Test 6：模块无效归因

### 必须包含的检查点

- [ ] R1: 使用 Failure Diagnosis Template 结构
- [ ] R2: 给出至少 2 条互斥的失败假设链
- [ ] R3: 每条链完整（变量 → 约束 → 代价 → 结果）
- [ ] R4: 给出最小验证实验
- [ ] R5: 区分事实、推断和假设

### 禁止出现的错误

- [ ] 只有一个解释
- [ ] 没有证据分层
- [ ] 直接断言而不给验证方法

---

## Test 7：创新点判断

### 必须包含的检查点

- [ ] R1: 按 Innovation Review Rule 的 5 个维度逐一判断
- [ ] R2: 给出"成立的条件"
- [ ] R3: 给出"不成立的风险"
- [ ] R4: 有参数量/计算量公平性分析
- [ ] R5: 有可证伪预测

### 禁止出现的错误

- [ ] 只说"不错的创新点"
- [ ] 没有维度判断
- [ ] 没有风险分析

---

## Test 8：工程设计——唯一索引包含 deleted

### 必须包含的检查点

- [ ] R1: 使用 Type E: Engineering Design 重点
- [ ] R2: 分析"软删除 vs 唯一约束"的矛盾
- [ ] R3: 给出索引 key 组合的变化
- [ ] R4: 给出一致性约束的代价权衡
- [ ] R5: 说明失败边界（并发问题）

### 禁止出现的错误

- [ ] 只说"防止重复数据"
- [ ] 没有分析软删除与唯一约束的矛盾

---

## Test 9：Evidence Level 强制检查

### 必须包含的检查点

- [ ] R1: 明确区分结构事实、机制推断、待验证假设
- [ ] R2: 结构事实使用标志词（改变、增加、减少）
- [ ] R3: 假设使用标志词（如果…那么…）
- [ ] R4: 不把推断写成事实
- [ ] R5: 说明 ERF 超过目标尺度后可能引入噪声的边界条件

### 禁止出现的错误

- [ ] 把"效果更好"写成必然结果
- [ ] 没有标注推断
